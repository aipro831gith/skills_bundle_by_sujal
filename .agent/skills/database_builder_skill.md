### Step 2 — Prisma Schema Generation (PostgreSQL standard)

```prisma
// prisma/schema.prisma
// Generated by Agent 07 — DO NOT EDIT MANUALLY

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

// FINANCIAL RULE: ALL monetary fields MUST be Int (cents), NEVER Float or Decimal
// Example: $10.99 stored as 1099 (integer cents)

model User {
  id            String    @id @default(uuid())
  email         String    @unique
  passwordHash  String    // Argon2id hash — never plaintext
  roles         String[]  @default(["user"])
  isActive      Boolean   @default(true)
  createdAt     DateTime  @default(now())
  updatedAt     DateTime  @updatedAt
  invoices      Invoice[]

  @@index([email])        // Index: high-frequency query column
  @@index([createdAt])
}

model Invoice {
  id              String        @id @default(uuid())
  userId          String
  totalCents      Int           // MUST be Int, NOT Float
  taxCents        Int           @default(0)
  status          InvoiceStatus @default(DRAFT)
  createdAt       DateTime      @default(now())
  updatedAt       DateTime      @updatedAt
  user            User          @relation(fields: [userId], references: [id], onDelete: Restrict)
  lineItems       InvoiceLineItem[]

  @@index([userId])        // Index: FK column
  @@index([status])        // Index: filter column
  @@index([createdAt])     // Index: sort column
}

model InvoiceLineItem {
  id              String   @id @default(uuid())
  invoiceId       String
  productId       String
  quantity        Int
  unitPriceCents  Int      // MUST be Int, NOT Float
  invoice         Invoice  @relation(fields: [invoiceId], references: [id], onDelete: Cascade)

  @@index([invoiceId])
}

enum InvoiceStatus {
  DRAFT
  SENT
  PAID
  CANCELLED
}
```

### Step 3 — Financial Transaction Pattern (MANDATORY for all payment/invoice operations)

```typescript
// services/transactionService.ts
import { prisma } from '../lib/prisma';

/**
 * ALL financial mutations MUST use SERIALIZABLE isolation.
 * NEVER use default READ COMMITTED for money operations.
 */
export async function createInvoiceWithItems(
  userId: string,
  lineItems: Array<{ productId: string; quantity: number; unitPriceCents: number }>
): Promise<{ invoiceId: string; totalCents: number }> {

  // Validate all inputs before starting transaction
  if (!userId || lineItems.length === 0) {
    throw new Error('ERR_VALIDATION: userId and at least one lineItem required');
  }
  for (const item of lineItems) {
    if (!Number.isInteger(item.unitPriceCents) || item.unitPriceCents < 0) {
      throw new Error('ERR_INVALID_CENTS: unitPriceCents must be non-negative integer');
    }
    if (!Number.isInteger(item.quantity) || item.quantity < 1) {
      throw new Error('ERR_INVALID_QTY: quantity must be positive integer');
    }
  }

  // SERIALIZABLE isolation — prevents phantom reads on concurrent invoice creation
  return await prisma.$transaction(async (tx) => {
    const totalCents = lineItems.reduce(
      (sum, item) => sum + item.unitPriceCents * item.quantity,
      0
    );

    const invoice = await tx.invoice.create({
      data: {
        userId,
        totalCents,
        status: 'DRAFT',
        lineItems: {
          create: lineItems.map(item => ({
            productId: item.productId,
            quantity: item.quantity,
            unitPriceCents: item.unitPriceCents,
          }))
        }
      },
      include: { lineItems: true }
    });

    return { invoiceId: invoice.id, totalCents: invoice.totalCents };
  }, {
    isolationLevel: 'Serializable',  // REQUIRED for financial operations
    maxWait: 5000,                   // 5s max wait for lock
    timeout: 10000,                  // 10s transaction timeout
  });
}
```

### Step 4 — Index Generation Policy

**Index ALL of these automatically:**
| Column Type | Rule | Example |
|-------------|------|---------|
| Primary key | Auto-indexed (Prisma @id) | `id` |
| Foreign key | MUST add @@index | `userId`, `customerId`, `orderId` |
| Filter columns (WHERE clauses) | MUST add @@index | `status`, `isActive`, `role` |
| Sort columns (ORDER BY) | MUST add @@index | `createdAt`, `updatedAt`, `name` |
| Unique fields | Auto-indexed (@unique) | `email`, `slug`, `sku` |
| Search columns | Consider full-text index | `description`, `title` |

**FORBIDDEN: Over-indexing** — Do NOT index columns with < 10 distinct values unless they are FK or frequently filtered.

## 4. STRICT TECHNICAL & SECURITY CONSTRAINTS (HARD RULES)

- **NEVER** define a monetary field as `Float` or `Decimal` in Prisma/SQL schema. ALL monetary values are `Int` (cents).
- **NEVER** use DEFAULT isolation level for financial transactions. MUST use `SERIALIZABLE`.
- **NEVER** hardcode `DATABASE_URL` or any connection string. Always `process.env.DATABASE_URL`.
- **NEVER** run `prisma db push` in production — ONLY `prisma migrate deploy` with reviewed migration files.
- **NEVER** drop a migration file once it's created. Create a new migration to reverse changes.
- **NEVER** delete production data in a migration without a Boss-confirmed backup procedure.

**NEVER DO:**
- Do not create FK relationships without @@index on the FK column.
- Do not use `@default(autoincrement())` for IDs in distributed systems — use `@default(uuid())`.
- Do not allow cascade DELETE on financial records (invoices, payments). Use Restrict.
- Do not seed production databases with test data.
- Do not commit `prisma/migrations/` lockfile conflicts unresolved.

## 7. ERROR HANDLING & ESCALATION MATRIX

| Error | Severity | Action |
|-------|----------|--------|
| `Float` type found on monetary field | CRITICAL | Surgical fix: change to `Int`. Write migration to convert existing data: `ALTER COLUMN price TYPE INT USING ROUND(price * 100)`. |
| Missing index on FK column | HIGH | Add @@index. Generate new migration. |
| SERIALIZABLE transaction removed | CRITICAL | Restore immediately. Financial data integrity requires it. |
| Prisma validate fails | HIGH | Fix schema errors. Do not generate migration until validate passes. |
| Migration conflict (two developers) | HIGH | Resolve by running `prisma migrate resolve`. Document resolution in diary_1. |
| Seed script fails | MEDIUM | Debug seed.ts. Check FK constraints — seed parent models before children. |
